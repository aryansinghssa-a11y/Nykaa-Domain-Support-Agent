# Nykaa E-commerce Support Agent

A task-based capstone project that builds an AI-assisted customer-support workflow for a Nykaa-style e-commerce use case. The implementation combines retrieval-augmented generation (RAG), order lookup and escalation logic, a LangGraph workflow, structured outputs, guardrails, API deployment, observability, MCP interoperability, SQLite checkpointing, and timeout/retry handling.

> **Project status:** Tasks 14–16 were run successfully in the development environment. Before submission, rerun the end-to-end checks described below and confirm that every required task artifact and evidence file is present.

## 1. Project capabilities

The project folder shown during development contains the following components:

- **Knowledge retrieval:** ChromaDB persistent vector store, with the `nykaa_sentence_chunks` collection, and Sentence Transformers using `sentence-transformers/all-MiniLM-L6-v2`.
- **Order operations:** order records in CSV format, escalation scores, and a reusable `check_order_status()` function in `order_lookup.py`.
- **Agent workflow:** LangGraph nodes for intent classification, policy retrieval, order lookup, and response composition.
- **Reliability and control:** guardrails, structured response schemas, persisted conversation memory, and structured logging.
- **Service layer:** FastAPI application in `app.py`.
- **Interoperability:** MCP server and client in `mcp_server.py` and `mcp_client.py`.
- **Durable execution:** SQLite checkpointing using `checkpoints.sqlite`.
- **Fault tolerance:** asynchronous per-node timeout, graph-level timeout, and retry policy with exponential backoff.

## 3. Requirements

- Python 3.10 or newer is recommended. Confirm the Python version used for your successful runs before fixing the version in the submission documentation.
- Install the packages listed in `requirements.txt` in a clean virtual environment.
- The Task 16 native LangGraph node-timeout demonstration requires a LangGraph release that supports node timeouts (`langgraph>=1.2.0`).
- The Sentence Transformers model may be downloaded the first time it is loaded. An internet connection may be required unless the model is already cached.
- Keep `knowledge_base/`, the order CSV files, and the ChromaDB persistence directory available at the paths expected by your code.

## 4. Setup on Windows

Open PowerShell in the project directory:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, use:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Run notebooks with Jupyter:

```powershell
jupyter notebook
```

## 5. Running the application

Start the FastAPI application from the project directory:

```powershell
uvicorn app:app --reload
```

Then open the FastAPI interactive documentation at:

```text
http://127.0.0.1:8000/docs
```

Use the routes actually defined in `app.py`; endpoint names and request schemas should be taken from the running `/docs` page rather than assumed from this README.

Run the MCP server and client using the commands and transport configured in the project scripts. For example, inspect `mcp_server.py` and `mcp_client.py` first, then run them in the separate processes required by the capstone brief. Do not assume a transport or command that differs from your implementation.

Run the observability interface only using the command specified in `observability_app.py` and its framework configuration.

SQLite `-wal` and `-shm` files are transient companion files. Close the application/checkpointer cleanly before packaging the database. Do not delete them while a process is using the database.
